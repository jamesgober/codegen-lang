# codegen-lang v1.0.1 — parallel-move fix

**A correctness patch.** `1.0.0` miscompiled loop back edges that pass a block's own parameters back to it in a different order. This release lowers every control-flow edge as the parallel copy SSA defines. There is no public API change; upgrading is a `cargo update`.

**Everyone on `1.0.0` should upgrade.** The bug produced wrong programs from IR that `ir-lang`'s validator accepts, with no error.

**aot-lang users:** `aot-lang` depends on `codegen-lang = "1"` and lowers through `compile`, so it inherited the miscompile. It picks the fix up on its next dependency resolution (`cargo update -p codegen-lang`), with no new `aot-lang` release needed.

## The bug (ISSUES H01)

A block argument list is a *parallel* assignment, like a phi: every argument is read before any parameter is written. `1.0.0` emitted one `move` per argument, in argument order. Its docs justified this by saying an edge's source and destination registers are disjoint in SSA. That is false for a loop back edge that passes the header's own parameters:

```text
H(a, b):  …  jump H(b, a)        // swap
1.0.0:       a = b; b = a        // both end up holding the old b

H(a, b):  a2 = a + 10;  jump H(a2, a)   // shift
1.0.0:       a = a2; b = a              // b receives the new a, not the old one
```

Duplication (`jump H(a, a)`) happened to lower correctly. Rotations, reversals, and any permutation with a cycle did not, on plain jumps and on either arm of a two-way branch.

## The fix

Each edge's copies now go through a parallel-move scheduler (`src/moves.rs`):

- A copy runs only once no pending copy still reads its destination. Running it may free the copy that overwrites its source.
- When only cycles remain, one copy's source is saved in a **scratch register** and that copy reads the scratch instead. The rest of the cycle then runs as a chain.
- Self-copies are skipped. The move count is minimal: one per copy whose source and destination differ, plus one per cycle. A swap costs 3 moves, and a `k`-cycle costs `k + 1`.
- An edge of up to 16 copies, which covers nearly every real edge, is scheduled in a stack buffer with no heap use. Its cost is a bounded scan, at most 16² comparisons per pass. A larger edge is scheduled in time linear in its copy count, using per-register side tables that are allocated once per function and cleared as each move is emitted.
- An edge with no conflicts lowers exactly as in `1.0.0`, in argument order.

The swap above now lowers to `s = b; b = a; a = s`.

### Visible effects

- **`register_count` grows by one** for a function where at least one edge has a cycle. The scratch register is numbered just past the value registers. Every other function's count is unchanged. The count stays exact: one past the highest register any op names.
- **Programs with a cyclic edge get different op streams**, because the old ones were wrong. Programs without one are op-for-op identical to `1.0.0`.

## Also in this patch (M51, patch-level parts)

- **Checked casts.** Every `as u32` in the lowering is now a checked conversion that cannot panic or wrap. Register numbers and block labels come from ir-lang's `u32` handles, so they always fit. A register count, internal label, or op offset could overflow `u32` only in a program with more than `u32::MAX` registers, labels, or ops, which the bytecode format cannot describe. In that case the value saturates instead of silently aliasing a register or label. The bound is documented on the conversion.
- **Program invariant check.** `Program::__check_invariants` is `#[doc(hidden)]` and **outside the SemVer promise**. It checks that the program is non-empty, that the entry label is op 0, that every register and parameter is in range, that parameters are distinct, that every label and jump target lies inside the op stream, and that the last op is a jump or return. Deserialization still does not validate. A public `Program::validate` and validating `Deserialize` are scheduled for `1.1.0`, because a patch cannot add API or reject input that `1.0.0` accepted (see `dev/ROADMAP.md`).
- **Faster disassembly.** `Display for Program` sorts the labels once instead of scanning all of them for every op. It now costs `O(ops + labels·log labels)` instead of `O(ops × labels)`, and its output is byte-identical (tested against the old loop).

## Tests added

- **Named regressions** (`tests/parallel_moves.rs`): swap, 3-cycle rotation, shift (`jump H(a2, a)`), duplication (`jump H(a, a)` and `jump H(b, b)`), a four-way reversal (two 2-cycles), a 40-parameter back edge that mixes an 18-cycle, ten 2-cycles, a chain, and a duplicate and so runs the table scheduler, a two-armed back edge that swaps on one arm and rotates on the other, and a conflict-free edge that keeps argument order. Each one is run in the bytecode interpreter and compared with a direct evaluation of the IR, and its move count is checked.
- **CFG properties** (512 cases each). Generated functions chain one to three counted loops. Their back edges are a jump or a two-armed branch, and the arguments are arbitrary permutations, rotations, reversals, duplications, and mixes of header parameters, the counter, body parameters, fresh body values, and function inputs. Every program is checked four ways:
  - its result matches a new IR interpreter (`tests/support/ir.rs`) that binds block arguments as a true parallel assignment;
  - it passes the invariant check and contains no self-moves;
  - its move count equals the minimum, computed independently from the IR;
  - its register count is exact.
- **Generator coverage.** A deterministic test samples 512 generated CFGs and requires that at least a fifth contain a cycle. About two thirds do. The test also requires duplications, two-armed back edges, and multi-trip loops to appear.
- **Scheduler unit and property tests** against a parallel-assignment reference, including a 100,000-register rotation.
- Run against the `1.0.0` lowering, the regressions and the CFG properties fail, so they detect the bug.

## Performance

These are Criterion means for `compile` (validation plus lowering), all from one Windows x86_64 machine. The `1.0.0` column was measured with the same benchmark file, including the new `rotating_loop` shape, built against the `1.0.0` lowering. The machine was noisy: shapes that this patch does not touch (`branch_chain`) moved ±15% between runs.

| Shape | 1.0.0 (wrong code on cycles) | 1.0.1 |
|---|---:|---:|
| `straight_line/4096` (no edges) | 53.3 µs | 51.6 µs |
| `branch_chain/512` (one-copy edges) | 196 µs | 169–193 µs |
| `loop_sum` (two-copy back edge, no cycle) | 1.06 µs | 0.96 µs |
| `rotating_loop/16` (one 16-cycle) | 1.04 µs | 1.39 µs |
| `rotating_loop/1024` (one 1024-cycle) | 8.5 µs | 18.3 µs |
| `rotating_loop/131072` (one 131072-cycle) | 2.35 ms | 3.93 ms |

Functions without conflicting copies cost the same as before. An edge of up to 16 copies is scheduled in a stack buffer without touching the heap. Above 16 copies, the scheduler allocates side tables sized to the function's register count, once per function. An edge that is one huge cycle costs about 1.7–2.2× more than the old single pass did. The old single pass produced wrong code for that edge.

## Verification

Local gate on Windows x86_64 (Rust stable 1.95 and the 1.85 MSRV):

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green. Test counts at this tag:

- `--all-features`: 34 unit tests (16 in `1.0.0`). Of the 18 new ones, 13 cover the move scheduler (4 of them property tests that check both the stack path and the table path against a parallel-assignment reference), 2 cover the lowering, and 3 cover program invariants and disassembly. There are 31 integration tests: 14 in `parallel_moves` (9 named regressions, 1 generator-coverage test, and 4 CFG properties at 512 cases each), 6 workflow, 5 invalid, 3 property, and 3 `serde`. There are also 15 doctests.
- Default and `--no-default-features`: the same, minus the 3 `serde` tests.

The coordinator still has to run the Linux / WSL2 and newest-toolchain gates.
